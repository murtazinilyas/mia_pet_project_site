# Python server для сайта ПК-Мастер

Этот каталог содержит HTTP-сервер, который обслуживает статический сайт и принимает заявки с формы обратной связи.

Сервер выполняет следующие задачи:

- раздаёт страницы из папки [../site](../site);
- принимает POST-запросы на `/api/request`;
- проверяет обязательное согласие на обработку персональных данных;
- отправляет заявку по SMTP на электронную почту;
- при наличии настроек отправляет уведомление в Telegram;
- пишет логи в консоль и, при необходимости, в файл.

## Как запустить

```bash
cd /path/python_server
python3 server.py
```

По умолчанию сервер слушает порт `8080`.

Если нужно изменить порт:

```bash
PORT=9000 python3 server.py
```

После запуска откройте:

```text
http://localhost:8080
```

## Как работает заявка

Форма заявки находится в [../site/request.html](../site/request.html).

При отправке JavaScript собирает данные и отправляет JSON на `/api/request`.

Пример запроса:

```json
{
  "name": "Иван",
  "phone": "+7 (999) 123-45-67",
  "city": "Бугульма",
  "service": "Ремонт компьютера",
  "address": "ул. Ленина, 10",
  "call_time": "после 18:00",
  "call_first": "yes",
  "message": "Компьютер не включается",
  "agreement": true
}
```

Важно: заявка принимается только при подтверждённом согласии на обработку персональных данных. Без этого параметра запрос отклоняется.

## Конфигурация

Настройки читаются из файла [config.env](config.env).

Пример:

```env
EMAIL_TO=your_mail
SMTP_HOST=smtp_host
SMTP_PORT=smtp_port
SMTP_USE_TLS=false
SMTP_USERNAME=your_mail
SMTP_PASSWORD=your_password
SMTP_FROM=your_mail

TELEGRAM_BOT_TOKEN=
TELEGRAM_CHAT_ID=
TELEGRAM_PROXY=

LOG_FILE=../logs/app.log
```

### Параметры

- `EMAIL_TO` — адрес, на который уходят письма с заявками.
- `SMTP_HOST`, `SMTP_PORT`, `SMTP_USERNAME`, `SMTP_PASSWORD`, `SMTP_FROM` — параметры SMTP.
- `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` — настройки Telegram-уведомлений.
- `TELEGRAM_PROXY` — необязательный прокси для Telegram API.
- `LOG_FILE` — путь к файлу логов, можно указывать относительный или абсолютный путь.

Если SMTP или Telegram не настроены, сервер пишет об этом в лог и продолжает работу, но не отправляет уведомления.

## Обработка входящего запроса

Сервер в [server.py](server.py) делает следующее:

1. принимает JSON с данными формы;
2. вызывает `validate_request_data()`;
3. проверяет обязательное поле `agreement`;
4. отправляет заявку по почте;
5. при наличии настроек отправляет сообщение в Telegram;
6. возвращает JSON-ответ клиенту.

## Логирование

Логи выводятся в консоль. Если переменная `LOG_FILE` задана, они дополнительно записываются в файл.

Каталог для логов создаётся автоматически, если он ещё не существует.

## Проверка

Для проверки валидации согласия используется тестовый файл [test_server.py](test_server.py).

Запуск:

```bash
cd /home/van/site
python3 -m unittest discover -s python_server -p "test_*.py" -v
```

Проверяются три сценария:

- заявка с подтверждённым согласием проходит;
- заявка без согласия отклоняется;
- заявка с выключенным чекбоксом отклоняется.

## Полезные замечания

- секретные данные не должны попадать в frontend-код;
- все настройки соединений хранятся в [config.env](config.env);
- для продакшена сервер лучше запускать на VPS, хостинге или в контейнере;
- локально проект удобно запускать через WSL, как в текущей среде проекта.
